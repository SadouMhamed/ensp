# ENSP — Company Website + Dashboard

A public company website plus a private dashboard where the team logs in to manage
website media (images, videos, files) and blog posts / articles.

| Layer | Tech |
|---|---|
| Framework (front + back) | **Next.js 16** (App Router, Server Actions, `proxy.ts`), **TypeScript** |
| UI | **shadcn/ui** (Base UI, `base-nova` style) + Tailwind CSS v4 |
| Database | **Neon Postgres** via **Drizzle ORM** + `pg` (node-postgres) pool |
| Auth | **Better Auth** (email + password, roles `admin` / `editor`) |
| Media storage | **Cloudflare R2** (S3-compatible). Only metadata goes in Postgres |
| Validation / forms | Zod + react-hook-form |
| Article editor | Tiptap |

## Initialization: what was done, step by step

### Step 1 — Create the Next.js app
`create-next-app` with TypeScript, Tailwind, ESLint, App Router, `src/` folder and the `@/*` import alias.
Next.js 16 ships with **Cache Components** enabled (`cacheComponents: true` in `next.config.ts`).
This means:
- Pages are static by default. Data is cached with `"use cache"` + `cacheTag()`.
- Anything that reads cookies or the session **must be inside `<Suspense>`**.
- Middleware is now called **`src/proxy.ts`**.
- The Next.js docs for this exact version are in `node_modules/next/dist/docs/`.

### Step 2 — Set up shadcn/ui
`shadcn init` + components: button, card, input, label, textarea, table, dialog, dropdown-menu,
sidebar, sonner (toasts), badge, separator, avatar, select, tabs, field, skeleton.
They live in `src/components/ui/`; you own them and can edit them.
Add more with `npx shadcn@latest add <name>`.

### Step 3 — Database: Drizzle + Neon
- `src/db/index.ts`: `pg` Pool on the **pooled** `DATABASE_URL` + `attachDatabasePool` (Neon's recommendation for Next.js on Vercel Fluid compute). Migrations use `DATABASE_URL_UNPOOLED` (direct).
- `src/db/schema/auth.ts`: user / session / account / verification tables (generated by the Better Auth CLI).
- `src/db/schema/content.ts`: our tables:
  - **media**: url, storage key, filename, type, size, dimensions, alt text, uploader
  - **posts**: title, slug, excerpt, content (Tiptap JSON), cover image, status draft/published, author, dates
  - **site_sections**: editable website blocks by `key` (e.g. `home_hero`) → title, text, media
- `drizzle.config.ts` + npm scripts `db:generate`, `db:migrate`, `db:push`, `db:studio`.

### Step 4 — Authentication: Better Auth
- `src/lib/auth.ts`: server config (email/password, `role` field, **public sign-up disabled**).
- `src/lib/auth-client.ts`: `signIn`, `signOut`, `useSession` for client components.
- `src/app/api/auth/[...all]/route.ts`: the auth API endpoints.
- `src/lib/dal.ts`: **Data Access Layer**: `getCurrentUser()`, `requireUser()`, `requireAdmin()`.
  Call these in every dashboard page **and every Server Action**.
- `src/proxy.ts`: fast redirect of `/dashboard/*` → `/login` when there's no session cookie.
- `scripts/seed.ts` (`npm run db:seed`): creates the first **admin** account from `.env`.

### Step 5 — Media, validation, editor libraries
- `src/lib/storage.ts`: R2 client, signed upload URLs, delete, allowed file types (50 MB max).
- `src/app/api/upload/route.ts`: authenticated endpoint that returns a signed upload URL.
  Flow: browser asks for URL → uploads file **directly to R2** → saves metadata in `media`.
- `src/lib/validations/`: Zod schemas shared by forms and server (`postSchema`, `slugify`, upload request).
- Tiptap installed (`@tiptap/react`, `@tiptap/starter-kit`) for the article editor.

### Step 6 — Project structure and pages
- Public site `(site)`: home, about, blog list, blog post `[slug]`, header + footer.
- `/login`: sign-in form (shadcn Card + Field).
- Dashboard `(dashboard)/dashboard`: shadcn sidebar layout, user card + sign out,
  pages: Overview, Blog & articles, New article, Media library, Settings (placeholders).
- `src/server/queries/posts.ts`: cached public reads (`getPublishedPosts`, `getPostBySlug`) + dashboard read.
- `src/server/actions/posts.ts`: `createPost` / `deletePost` with auth checks + `updateTag("posts")`
  so the public blog updates instantly after publishing.

### Step 7 — Verification
`npm run typecheck` ✔ · `npm run lint` ✔ · `npm run build` ✔ ·
routes respond, and `/dashboard` redirects to `/login` when signed out ✔

## Neon setup (done)

The project is linked to Neon project `odd-boat-26415790`, branch `production` (`.neon`, git-ignored),
with infrastructure declared in `neon.ts`. `neon deploy` pulled `DATABASE_URL`, `DATABASE_URL_UNPOOLED`,
`NEON_BRANCH`, `NEON_BRANCH_ID` and `NEON_FUNCTION_HOST_SUFFIX` into `.env`.
Migrations are applied and the first admin exists.

On a new machine:
```bash
npm i -g neon
```
```bash
neon login
```
```bash
neon env pull
```
```bash
npm run dev
```

Before going live: set your real `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` in `.env` and run `npm run db:seed`,
then remove the `admin@example.com` test admin. Fill in the `R2_*` variables when you build the media library.

```
├── components/
│   ├── ui/                     shadcn components
│   ├── site/                   public site components
│   └── dashboard/              dashboard components

├── lib/                        auth, DAL, storage, validations, utils

│   └── queries/                data reads

scripts/seed.ts                 first admin
```
